## 1. 本次改了什么

### 1.1 新增 UI 无关内核 `web/js/stack-core.js`

`window.StackCore` 不依赖 DOM、不依赖 sandbox 的 state 形状：

| API | 用途 | 复用方 |
|---|---|---|
| `createLedger({layers,temp,events,...})` | 层数账本：`add/get/set/snapshot/restore`，999 封顶，事件字段 `kind/detail/tier/markerUid` | 沙盒；配队将来按词条试算 |
| `createEventBus()` | 事件总线：`on/off/emit/has`，按 priority 排序，once | 沙盒的盟约级钩子 |
| `createMetrics(initial)` | 冻结/沉睡/元素爆发/装备/资金等计数源，只计数不建实体 | 未来 special 机制 |
| `ruleText(rule)` | 统一规则文本，带 `onKnockdown/onSubstitute/onMetric` 标签 | 沙盒详情；配队词条 |
| `sellPriceOf(name,{elite,bonus,cap})` | 售出价：默认 1，温蒂 3/6，支持修正/封顶 | 旅骨/棘刺；配队价格展示 |

`web/sandbox.html` 已引入该文件（gzip 约 3.4 KB）；`web/index.html` **默认不加载**，因为首屏 gzip 预算（当前构建脚本为 123 KB）需要留给 `calc.js` 的特殊上限表。配队需要时动态插入 `js/stack-core.js`（或只加载 `ruleText/sellPriceOf` 的精简版），`team.js` 顶部注释记录了端口。

### 1.2 `sandbox.js` 的接入

- `addLayer()` 的账本/事件部分改为调用 `StackCore.createLedger()`；日志、999 警告、盟约存在性校验仍留在 sandbox。
- 新增 `BUS = StackCore.createEventBus()`；`beginBattle()` 通过 `BUS.emit('battleStart')` 执行盟约钩子，再跑现有 `triggerEvent('onBattleStart')`，保持干员规则兼容。
- 新增 `state.metrics`（`StackCore.createMetrics()`），为后续 `onMetric` 预留；本次未接 UI。
- 新增 `state.battleStartDone / egirStarted / sellPriceBonus`。

### 1.3 阿戈尔吞噬（盟约级，而非干员名）

- `planEgirDevour()`：按本地坐标 `c` 升序、`r` 升序（本地 `r=0` 是顶部）；`frontOp()` 取身前一格；队列穿过被标记的阿戈尔连链；`seen/markedBy` 防环；同名阿戈尔去重。
- `applyEgirDevour()`：每个“不同的被标记单位”只加一次层数 = 其等阶；`state.egirStarted` 保证每场只结算一次；事件 `kind:'bond:devour'`、`detail:'吞噬'`、`tier/markerUid` 供报表使用。
- `beginBattle()` 先跑吞噬，再跑干员 `onBattleStart`。

### 1.4 助力 / 生命周期 / 售价 / 事件

- **助力**：`applyDeputLayers()` 在 `onPrepEnd` 后给所有已激活盟约 +2；3 名不同/精锐 +4。通过 `getEval()` 的 `empowered` 判断，不写死 2/3。
- **battleStart 幂等**：`beginBattle()` 检查 `state.battleStartDone`；`battleStart` 重复触发只提示；`battleCounters` 只在进入战斗时清一次。
- **报表时点**：`prepEnd` 中先 `onPrepEnd → applyDeputLayers → generateReport('休整期')`，再 `beginBattle()`；吞噬归作战期报表。
- **售价**：`sellPriceOfOp()` 改读 `StackCore.sellPriceOf()`；`priceSum/priceTarget/priceSelf` 都不再用采购价。默认 1，温蒂 3/6；`state.sellPriceBonus` 为海沫等修正预留。
- **事件修正**：`EVENT_FIXES` 把远牙改 `onKill`，耀骑士临光/归溟幽灵鲨/风丸/历阵锐枪芬改 `onKnockdown`；新增 `onKnockdown` 事件标签与“我方击倒”按钮（已接入 `renderEventBar`/`EVENT_TIP`，选中干员后触发）。
- **convert 封顶保护**：折桠/乌啾的“临时转固定”先扣 `state.temp` 再 `addLayer`，999 封顶时会白吃临时层；现在先算 `room`，只扣实际能转的层数。
- **特质/快照**：`battleEnd` 清空 `grantedTraits`，`retreat` 同时清理来源；快照带 `battleStartDone/egirStarted`，导入作战期不会重复吞噬。
- **onSell/onSubstitute**：仅加事件标签/预留，尚未派发；`onSell` 规则仍显示 special。

### 1.6 特殊叠层上限（一键补满）

- `calc.js` 新增 `Calc.SPECIAL_CAPS`，把 9 名“仍只有 special 文本、但有明确上限”的干员表列出来：初雪、圣聆初雪、妮芙、烛煌、余、佩佩、溯光星源、耀骑士临光、浊心斯卡蒂。
- `sandbox.js` 新增 `applySpecialBattleCaps()`，由 `applyBattleCaps()` 调用；按 `self` / `selfAndBehind1` 目标、`activeSelf` / `activeAll` / 固定盟约解析，使用 `state.counters`/`battleCounters` 防重复，补到上限。
- 配队 `team.js` 的 `traitGroups()` 对表内干员优先使用 `Calc.SPECIAL_CAPS`，不再走文本 `parseTraitCaps`，从而与沙盒一键补满同源；表外干员仍走原文本解析。
- 注意：这是**上限补满**，不是事件模拟；初雪/妮芙等仍不会自动感知“冻结/恐惧”次数。

### 1.5 测试与审查工具

## 3. 文本审查结论

### 3.1 已确认并修复

| 问题 | 证据 | 修复 |
|---|---|---|
| 旅骨/棘刺按采购价加层 | 文本“售出价格”，本地 `data.js` 无 `sellPrice`；参考 `price 2/3/4 → sellPrice 1` | `stack-core.sellPriceOf()`；售价测试 |
| 远牙事件误判 | 文本“敌人被击倒”，规则 `onDeploy`（“再部署时间”误导） | `EVENT_FIXES` → `onKill` |
| 耀骑士临光/归溟幽灵鲨/风丸/历阵事件误判 | 文本“被击倒/替身”，规则 `onKill`/`onDeploy` | `EVENT_FIXES` → `onKnockdown`（风丸可结算；其余 3 名仍 special，见 §3.2） |
| battleStart 可重复 + 报表混期 | 烈夏无上限 `onBattleStart temp`；`generateReport` 在 `onBattleStart` 后 | 幂等 + 报表时点 |
| convert 封顶白吃临时层 | 折桠/乌啾先扣 `state.temp` 再 `addLayer`，999 时返回 0 | 先算 `room`，只扣实际转化层数 |
| 特质跨场残留 | `battleEnd` 不清 `grantedTraits`，撤退不清来源 | 战斗结束/来源离场时清理 |
| 阿戈尔吞噬缺失 | 文本“战斗开始时吞噬”，无实现 | `applyEgirDevour()` |
| 助力缺失 | 文本“休整期结束所有已激活盟约 +2/+4”，无实现 | `applyDeputLayers()` |

### 3.2 仍未覆盖（明确保留）

- **11 名 special 加层**：初雪、圣聆初雪、妮芙、烛煌、余、佩佩、涤火杰西卡、溯光星源、耀骑士临光、塔露拉、矩。已有上限的 9 名已接入“一键补满/配队上限”，但**事件本身仍不模拟**（冻结/恐惧/元素爆发/调度中心等）；涤火杰西卡无上限、塔露拉/矩是修正/动态值，仍需后续机制。
- **投资人 / 调和**：`投资人` 的 ×2/×3 与本地锡人 `+4/+8` 是否存在“内建倍率”仍未定；`调和` 的“享受核心效果”只做到 Calc 人数 +1，未做 `isMember`。这两条会影响总量，建议下一期先核对再开。
- **层数缩放**：40 条 / 20 名“每叠加 N 层→攻击力/攻速…”仍是 special；层-only 沙盒只应展示当前层数代入，不模拟战斗数值。
- **海沫售出价修正**：`sellPriceBonus` 已预留，但海沫的 +1/+2（cap 4/8）尚未在 `onPrepEnd` 写入。
- **onSell/onSubstitute 派发**：只有标签；`onSell` 9 条规则仍未触发/提示。

## 4. 配队复用端口

`web/sandbox.html` 已加载 `js/stack-core.js`；配队默认不加载（守住当前 123 KB 首屏预算），需要时动态插入该脚本即可。配队可逐步接入：

```js
const ledger = StackCore.createLedger({ layers: {}, temp: {} });
ledger.add('精准', 2, '灰喉 · 获得时', { opName: '灰喉' });
StackCore.ruleText({ event: 'onGain', bonds: ['精准'], amount: 2 });
StackCore.sellPriceOf('温蒂', { elite: false }); // 3
```

当前配队不需要整支队伍模拟；最小用法是：
1. 用 `ruleText()` 统一词条说明；
2. 用 `sellPriceOf()` 修价格展示；
3. 若做“按词条试算层数”，用 `createLedger()` 在 `team.js` 内部建临时账本，不依赖 sandbox 的 `state`。

`StackCore` 没有 DOM、没有 `state` 全局、没有 `renderAll`，因此不会把沙盒的 UI 依赖带进配队。

## 5. 剩余风险与建议

| 风险 | 说明 | 建议 |
|---|---|---|
| 原始规则数据仍含旧事件 | 运行时修正只在 sandbox；别的地方直接读 `operator_rules.js` 会看到旧值 | 下一期把 `EVENT_FIXES` 写回生成器/数据，审计工具切换为 error |
| 投资人/调和未接 | 层数总量仍可能偏低 | 先核对锡人/灰喉是否内建倍率，再实现 |
| 11 special 未接 | 用户会看到“未模拟” | 按 `state.metrics` + `onMetric` 分批接，不要一次性做 |
| 海沫售价修正未接 | 旅骨/棘刺读不到修正后的售价 | 在 `onPrepEnd` 写入 `state.sellPriceBonus`，并加 cap |
| capAura 的“每回合/每场”口径 | 薇薇安娜文本是“本回合战斗期上限+7”，Mon3tr 文本是“每场战斗上限+30%”；现有引擎把 capAura 同样加到 perRound，测试也按此断言 | 这是产品口径而非单纯代码 bug；若确认 Mon3tr 只该影响 perBattle，再拆 `roundCapParts` 并改 2 个报表测试 |
| 同名干员重复上场 | `egirMembers()` 按名字去重（与 Calc 的“不同干员”一致），第二份同名 Aegir 不会吞噬；沙盒手牌允许重复 | 若产品允许重复，需要单独定“同名是否算不同单位”；当前按“不重复计数”处理并保留测试 |
| 事件总线只用在一个钩子 | 目前只有 battleStart 走 BUS；干员规则仍走旧 `triggerEvent` | 下一期把 `onKnockdown/onSell/onMetric` 也接到 BUS，逐步替换 |
| 测试仍偏少 | 58 项覆盖新增主链路，但未覆盖全部 304 条规则 | 用 `audit_sandbox_rules.mjs` 做静态门禁，再按机制补动态测试 |
