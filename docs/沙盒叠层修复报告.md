# 沙盒叠层修复报告

日期：2026-11-11  
范围：`web/js/sandbox.js`、`web/sandbox.html`、`web/data/operator_rules.js` 的消费逻辑、`tools/test_sandbox.mjs`

## 结论

`web/js/sandbox.js` 此前是未完成的半成品：文件只有 914 行，缺少规则引擎、事件处理、拖放/朝向、仓库与手牌管理、大部分渲染函数等约 1,700 行代码，页面启动时会在 `renderAll()` 里直接 `ReferenceError`。本次先补齐模块，再逐项核对 `operator_rules.js` 的字段与文本，修复了精英/普通分支、`bonds: "active"`、按人数/获得/刷新/整备区叠层、售价倍率、免费刷新、特质、战斗叠加上限等通用规则，并把 13 名原本只有 `special` 文本的干员接入了可结算模型。

回归测试：`node tools/test_sandbox.mjs` **42 项全部通过**；仓库原有 `test_calc` 29 项、`test_code` 7 项、`test_special` 10 项、`smoke_team` 45 项均通过；`python tools/build_dist.py --no-zip` 自检通过。

## 对反馈日志的复核（黑键 / 华法琳）

反馈日志里没有出现任何“开启技能”或“击倒敌人”事件，只有“战斗上限”点击。因此：

- **黑键**：规则是 `<战斗中>攻击范围内每有敌人被击倒 ...（每回合至多叠加 8 层）`，属于 `onKill + perRound`。旧“战斗上限”只补 `perBattle`，不会补 `onKill` 的每回合上限，所以黑键一直是 0。现在点“补满叠层”会补到 8 层（若【莱塔尼亚】未激活则只补【精准】，并在日志里说明）。
- **华法琳**：自身没有直接加层规则，只是战斗开始时给身前一格（日志中的霍尔海雅）一个“开技能时 +1/每回合至多 7 层”的特质。旧“战斗上限”不会触发特质，日志里也没有霍尔海雅开技能，所以特质一直是未消耗状态。现在“补满叠层”会把已获得特质按 perRound 上限补到目标；实际点“开启技能”时，霍尔海雅自身 +4 与特质 +1 共 +5，已用反馈码做回归测试。

这次复核同时修掉了第 25–28 行的同类问题。

## 报表显示：按盟约来源显示实际贡献与上限构成

报表保留原来的“按盟约汇总”，以 R2 的【精准】为例：

```text
精准
+48
来源
霍尔海雅 +19（12+7）
黑键 +15（8+7）
华法琳 +14（7+7）
```

- `+48` = 霍尔海雅 19 + 黑键 15 + 华法琳 14；
- 黑键 `+15（8+7）`：自身每回合上限 8 + 薇薇安娜 7；
- 霍尔海雅 `+19（12+7）`：自身每场战斗上限 12 + 薇薇安娜 7；
- 华法琳 `+14（7+7）`：特质上限 7 + 薇薇安娜 7（实际受益者是霍尔海雅，来源仍记在华法琳名下）；
- 每个来源只要有上限光环加成都会显示括号，不再只对黑键/每回合规则特判；
- 没有光环、且已经补满时，不显示多余括号，例如 `霍尔海雅 +12`；
- 未补满时显示 `/ 上限 N`，例如 `黑键 +5 / 上限 15（8+7）`。

不再额外显示“干员叠层”汇总区块；报表回到“盟约 → 来源”的结构，避免出现 `（24）` 这种把两个盟约上限合并、无法对应日志的数字。

### 上限光环不再按干员名写死

上限光环改成规则字段，任何带 `capAura` 的干员都会自动参与报表：

```js
capAura: {
  type: 'pct' | 'flat',
  value: 0.3,
  target: 'adjacent' | 'front' | 'sharedTag',
  requireTags: ['谢拉格', '灵巧'],
  order: 10
}
```

- 薇薇安娜：`flat +7 / sharedTag`；
- Mon3tr：`pct 30% / adjacent`；
- 凛御银灰：`pct 75% / front + requireTags`；
- 以后新增 M3 或其它光环，只要在对应规则里写 `capAura`，报表会自动按 `base + 光环1 + 光环2 + …` 展示，不需要再改报表代码；
- 多个光环按 `order` 排序，因此会稳定显示成 `8+3+4` 这类构成。

### 其它按名字写死的机制

本轮继续把三个名字判断改成规则字段：

- **阿米娅（医疗形态）**：`layerGainAura: { target:'front', amount:1/2 }`，由 `layerGainBonus()` 扫描所有带该字段的规则；
- **荒芜拉普兰德**：`teamWideKill: { killerTag:'叙拉古' }`，由 `handleTeamWideKill()` 扫描场上所有带 `teamWide` 的规则，不再写死干员名/精锐判断；
- **Mon3tr 提示**：`renderHint` 和格子 tooltip 改为读取选中的 `capAura`，薇薇安娜/凛御银灰/未来 M3 都会显示对应提示。

**浊心斯卡蒂 / 阿戈尔部署光环本轮未改代码**（按你的要求只给思路）：`handleDeployAuras()` 仍按名字和 `阿戈尔` 常量处理，下一步可用 `allyDeployAura` 字段替换，具体设计见最终说明。
