# 自选干员阵营审计（2026-11-14）

> 起因：有反馈指出自选干员的核心盟约可能与游戏内不一致，例如焰影苇草应为【协防干员】而非【维多利亚】。  
> 结论：**主表「游戏阵营 / 隐藏阵营」本身与解包一致（66/66），错在「核心盟约」的推导口径。**  
> 处置：按解包 `mainPower` 的最具体阵营 + 隐藏阵营重新推导，修正 5 名干员；发布 **1.0.6**。

---

## 1. 口径

PRTS「卫戍协议」原文：

> 自选加入的干员会根据其**实际阵营所属**分配核心盟约，若没有可匹配的则改为分配**协防干员**盟约。

解包数据把「实际阵营」拆成两层：`character_table.mainPower`（所属国家 / 组织 / 团队）与 `subPower`（隐藏阵营）。  
本季 10 个核心盟约的 `powerIdList` 在 `activity_table.autoChessData.bondInfoDict`：

| 核心盟约 | powerIdList |
| --- | --- |
| 炎 | `yan, sui, lungmen, lee, lgd` |
| 萨尔贡 | `sargon` |
| 维多利亚 | `victoria, glasgow` |
| 谢拉格 | `kjerag, karlan` |
| 阿戈尔 | `egir, abyssal` |
| 叙拉古 | `siracusa, chiave` |
| 卡西米尔 | `kazimierz, pinus` |
| 乌萨斯 | `ursus, student` |
| 伊比利亚 | `iberia` |
| 莱塔尼亚 | `leithanien` |

推导规则（`powerLevel`：team 2 > group 1 > nation 0，见 `handbook_team_table.json`）：

1. 取 `mainPower` 中层级最高的阵营（最具体的「实际阵营所属」）；
2. 并入 `subPower` 的全部阵营（隐藏阵营）；
3. 与上表 `powerIdList` 求交，命中的核心盟约全部保留；
4. 交集为空 → **协防干员**。

例：焰影苇草 `mainPower = victoria / tara`，最具体为 **塔拉**（group）；`subPower` 为空。塔拉不在任何核心的 `powerIdList` 中 → **协防干员**。  
例：煌 `mainPower = rhodes / elite`，`subPower = yan / victoria` → 最终并入 炎、维多利亚 → **炎 / 维多利亚**（与旧值一致）。

### 为什么不是「mainPower 全并集」

旧实现把 `mainPower` 的国家与组织平权（`victoria` + `tara` 同时参与），焰影苇草因此命中 `victoria` → 维多利亚。  
这与「实际阵营所属」不符：她的实际所属是**塔拉**（深池），而塔拉不在本季任何核心盟约的 `powerIdList` 里。  
本次改为「只取最具体的主阵营，再并入隐藏阵营」，差异只落在多阵营干员身上：

| 干员 | mainPower | 旧并集 | 新口径 |
| --- | --- | --- | --- |
| 焰影苇草 / 死芒 | victoria / tara | 维多利亚 | **协防干员** |
| 能天使 / 新约能天使 | lungmen / penguin；sub laterano | 炎 | **协防干员** |
| 缄默德克萨斯 | lungmen / penguin；sub siracusa | 炎 / 叙拉古 | **叙拉古** |

> 固定 143 名的盟约是策划在模式数据里写死的（`charChessDataDict[*].bondIds`），两种口径对它的回测都是 139/143 吻合，不能用来区分口径；自选干员的动态分配最终以游戏内自选编队界面为准。本次按「焰影苇草 = 协防干员」的实测反馈与「实际阵营所属」采用最具体口径。

> 拉特兰：本季 `V3_1.bondInfoDict` 只有 26 条盟约，不含 `lateranoShip`，因此拉特兰系干员（菲亚梅塔、塑心、圣约送葬人、信仰搅拌机、结城理）仍为**协防干员**，本次未改。

## 4. 复现

```bash
# 1) 离线快照：source/unpacked/pick_factions.json（解包 character_table / handbook_team_table / activity_table）
# 2) 审计主表 66 行与解包推导是否一致
python tools/check_pick_factions.py --detail
# 3) 重建数据 / 发布
python tools/build_web_data.py
python tools/build_dist.py
```

`build_web_data.py` 每次构建都会用同一口径复核；不一致会以 ERROR 中止，避免再出现「主表手写值」与解包脱节。
